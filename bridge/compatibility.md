# Product compatibility

All releases use the shared bridge for some operations. The following boundaries are part of their supported configuration, not a blanket promise of every combination.

| Product | Release | Required manifest dependencies | Integration boundary |
| --- | --- | --- | --- |
| [Advanced Car Radio](../products/advanced_car_radio/README.md) | 1.2.0 | `mm_bridge`, `ox_lib`, `oxmysql`, `xsound` | Requires xSound for audio, oxmysql for persistence and ox_lib. No target/inventory/phone adapter is required. Provider changes do not move saved radio ownership automatically. |
| [Advanced Cablecar](../products/advanced_cablecar/README.md) | 1.8.0 | `ox_lib`, `mm_bridge` | Optional targets still call ox_target directly. Ticket-machine proximity interactions work without a target provider. Config.Framework='standalone' explicitly skips fares; legacy 'qbox' selects paid bridge behavior. Framework selection in mm_bridge does not override this resource fare setting. |
| [Advanced Poolcleaner](../products/advanced_poolcleaner/README.md) | 1.2.0 | `mm_bridge`, `ox_lib`, `oxmysql` | Optional item requirements default to Inventory.mode='none'. Select mode='bridge' for generic bridge inventory reads. Required item mutations and payouts must be confirmed; failed payout completes progression but records zero earnings and needs staff reconciliation. |
| [Advanced Diving](../products/advanced_diving/README.md) | 1.1.0 | `mm_bridge`, `ox_lib`, `ox_target`, `oxmysql` | This release still directly requires ox_target for its job NPC. Choosing qb-target/qtarget in mm_bridge does not replace that integration. Optional gear checks use the bridge; gear is not consumed. Failed crew payout completes progression with zero credited earnings and requires reconciliation. |
| [Advanced Orbital](../products/advanced_orbital/README.md) | 1.3.0 | `mm_bridge`, `ox_lib`, `oxmysql` | Active job/grade/duty, ACE or public terminal access is checked server-side. Standalone without a custom economy requires DefaultPrice and every terminal's price to be zero. oxmysql and the supplied SQL are still required. |
| [Advanced Pausemenu](../products/advanced_pausemenu/README.md) | 5.2.0 | `ox_lib`, `mm_bridge` | The bridge reads inventory items but has no UI-open or weight API. Configure Inventory.command or a confirmed client Inventory.open hook; getWeight is a local hook. Unsupported balances show as unavailable. Service counts use duty but are not currently rendered by the UI. |
| [Advanced Yacht](../products/advanced_yacht/README.md) | 5.2.0 | `ox_lib`, `oxmysql`, `mm_bridge`, `/onesync` | Items and money use the bridge. Stashes are a local secured extension: ox_inventory and TGIANN are provided; QB/custom stash support requires an adapter with real open/transfer controls. Framework changes do not migrate yacht ownership or stash contents. |
| [Advanced Smoking](../products/advanced_smoking/README.md) | 1.1.0 | `mm_bridge`, `ox_lib`, `oxmysql`, `/onesync` | Full item use requires individual slots and persistent metadata. Plain ESX inventory and standalone without a suitable inventory cannot run the full system. QB inventory supports ordinary items; containers remain locked until a safe local stash adapter is configured. Shop credits marked processing/review require reconciliation. |
| [Advanced Government](../products/advanced_government/README.md) | 2.1.0 | `mm_bridge`, `ox_lib`, `oxmysql` | Default native job synchronization is QBox only; QBCore/ESX/standalone use SQL political roles unless custom job sync is configured. Default society settlement still needs NRP resources/schema or an atomic custom society adapter. Payroll tax is an opt-in export, not an automatically installed payroll hook. |
| [Advanced Vet DLC](../products/advanced_vet_dlc/README.md) | 15.11.0 | `oxmysql`, `ox_lib`, `mm_bridge` | Prescription items need slot/metadata support. Plain ESX inventory cannot preserve prescription metadata. Bridge billing supports own invoices; NRP retains clinic SQL lists, other clinic-wide lists need a hook. Needs and inventory item-definition/tooltip introspection remain local extensions. Patient IDs default to legacy licenses. |
| [Advanced K9](../products/advanced_k9/README.md) | 95.1.0 | `oxmysql`, `ox_lib`, `mm_bridge` | Standalone service authority needs ACE or explicit opt-in; civil play remains available. Needs and optional legacy phone adapters remain local extensions. The existing K9 UI and Vet exports are retained. Database keys default to legacy licenses; character mode requires a manual migration. |

Framework/inventory switches do not migrate historical identity keys, SQL ownership or stash contents. Back up and map actual character IDs before a switch. Live cross-provider certification is not included.
